# COURTBOARD

동호회·학교 경기를 위한 브라우저 기반 농구 전광판입니다. 별도의 서버 데이터베이스나 빌드 과정 없이 HTML, CSS, JavaScript로 동작합니다.

## 포함 기능

- 5대5: 기본 10분 × 4쿼터, 시간·쿼터 수 설정
- 3x3: 기본 10분, 12초 샷클락
- 게임클락과 샷클락의 독립적인 시작·정지 및 시간 보정
- 샷클락 10초 이하, 게임클락 1분 미만의 소수점 한 자리 표시
- 점수, 팀파울, 공격권, 타임아웃 표시
- 타임아웃: 전반 2회, 후반 3회, 연장마다 1회 (3x3는 경기 전체 1회)
- 단일 모니터 전광판 및 외부 모니터 전용 뷰어
- 대회별 여러 경기 사전 등록, 결과 저장, JSON 백업·복원
- 게임클락·샷클락 종료 버저 및 키를 누르는 동안의 수동 버저
- 서비스 워커를 통한 최초 접속 후 오프라인 사용

## GitHub에 올리기

이 폴더의 내용 전체를 저장소 루트에 올리세요. `dist/`, `test.cjs`, `package.json`, `.github/` 등이 저장소 루트에 있어야 합니다.

새 GitHub 저장소를 만든 다음, 이 폴더에서 실행합니다.

```sh
git init -b main
git add .
git commit -m "Initial COURTBOARD export"
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

`YOUR_USERNAME`과 `YOUR_REPOSITORY`를 실제 이름으로 바꾸세요. 위 명령은 내용이 없는 새 저장소를 기준으로 합니다.

## GitHub Pages로 실행하기

1. 저장소의 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
2. `main` 브랜치에 푸시하거나, **Actions → Deploy COURTBOARD to GitHub Pages → Run workflow**를 실행합니다.
3. 배포 완료 후 Pages 주소를 엽니다.

포함된 워크플로는 테스트 후 `dist/`를 게시합니다. 기본 브랜치가 `main`이 아니면 `.github/workflows/pages.yml`의 브랜치 이름을 변경하세요. Pages 설정과 배포는 이 내보내기 작업에서 실행하지 않았습니다.

GitHub Pages의 웹사이트는 일반적으로 공개됩니다. 기존 Sites의 로그인·접근 제한은 이 소스에 포함되지 않습니다. 저장소 공개 범위와 Pages 제공 여부는 본인의 GitHub 계정·저장소 설정을 확인하세요.

## PC에서 로컬 실행

Python 3이 설치되어 있다면 프로젝트 폴더에서 다음을 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Windows에서는 `python3` 대신 `py`를 사용할 수 있습니다. 브라우저에서 `http://localhost:8000`을 여세요. 서버 종료는 터미널에서 Ctrl+C입니다.

HTML 파일을 더블클릭하는 `file://` 방식은 사용하지 마세요. 저장·외부 창 동기화·서비스 워커 기능을 위해 HTTP localhost 또는 HTTPS로 실행해야 합니다. 이 localhost 주소는 같은 PC에서만 사용할 수 있습니다. iPad에서는 HTTPS로 게시된 주소를 여세요.

## 화면 사용법

- **단일 모니터:** 전광판을 표시하며 오른쪽 아래 **⚙ 메뉴**에서 세부 조작을 엽니다.
- **외부 모니터:** 메인 화면에 조작 버튼을 표시합니다. **외부 뷰어 열기**로 연 창을 유선 확장 모니터로 직접 옮기세요.
- 외부 뷰어는 전체·계시기·점수 중 선택할 수 있습니다. 점수 뷰어에는 팀파울도 표시됩니다.
- 조작 창과 뷰어는 같은 기기의 같은 브라우저 프로필·사이트 주소에서 사용하세요. 다른 기기 사이의 원격 동기화는 지원하지 않습니다.
- iPad의 확장 화면 및 창 이동 가능 여부는 기기·운영체제 지원에 따릅니다.

## 키보드

문자 입력란이나 설정 창에서는 경기 단축키가 동작하지 않습니다. 물리 키 위치(`KeyboardEvent.code`)를 기준으로 처리합니다.

| 기능 | 키 |
| --- | --- |
| 샷클락 14초 | Q (5대5) |
| 샷클락 24초 / 3x3 12초 | W |
| 샷클락 시작·정지 | E |
| 샷클락 +1초 / −1초 | R / F |
| 경기시간 시작·정지 | O |
| 경기시간 +1분 / −1분 | U / J |
| 경기시간 +1초 / −1초 | I / K |
| 홈 +1 / +2 / +3점 | A / S / D |
| 홈 −1점 / 파울 +1 / 타임아웃 | Z / X / C |
| 원정 +1 / +2 / +3점 | 따옴표 키 / 세미콜론 키 / L |
| 원정 −1점 / 파울 +1 / 타임아웃 | 슬래시 / 마침표 / 쉼표 |
| 수동 버저 | H를 누르는 동안 |
| 다음 쿼터·연장 | N (확인창 표시) |
| 공격권 왼쪽 / 오른쪽 | ← / → |

3x3에서는 +3점 키를 사용하지 않습니다. G·B·P에는 팀명 변경이나 경기 리셋을 연결하지 않았습니다. 샷클락 리셋 후에는 E로 다시 시작합니다. 타임아웃은 사용 개수만 변경하며 시계를 정지시키지 않습니다.

## 데이터 이전·백업

경기 데이터는 **브라우저의 localStorage**에 저장됩니다. 이 소스 ZIP에는 실제 사용자의 대회·경기 기록이 포함되지 않습니다.

기존 사이트에서 **대회 백업 ↓**으로 JSON을 받은 후 새 주소에서 **백업 복원 ↑**으로 불러오세요. 주소, 브라우저, 기기가 바뀌면 기존 저장 기록이 자동으로 따라오지 않습니다. 복원은 해당 브라우저의 전체 대회 목록을 교체합니다.

## 오프라인·소리

처음에는 인터넷이 연결된 상태로 접속하고 ‘오프라인 준비 완료’를 확인하세요. 이후 같은 브라우저에서 오프라인으로 사용할 수 있습니다. 브라우저 저장소를 지우면 캐시와 기록도 사라질 수 있습니다.

브라우저 오디오 정책 때문에 첫 사용자 입력이 필요할 수 있습니다. 경기 전에 메뉴의 **♪ 소리 확인**으로 출력 장치와 음량을 확인하세요. 자동 버저는 약 3초이며 샷클락 리셋·14초 입력은 샷클락 버저를 중단합니다. PC 정상 동작은 사용자 확인을 받았으며, iPad 버저 출력은 실기기 검증이 필요합니다.

3x3 21점 승리와 연장 2점 선취 등 승리 판정은 운영자가 확인하고 수동 종료합니다.

## 개발·검증

Node.js 20 이상에서 별도 패키지 설치 없이 실행합니다.

```sh
npm test
```

`test.cjs`는 점수·타임아웃·독립 시계·단축키·버저 제어를 모의 DOM/오디오 환경에서 검증합니다. 실제 브라우저 렌더링이나 스피커 출력을 검증하는 테스트는 아닙니다.

앱 파일은 `dist/` 안에 있습니다. 오프라인에 배포되는 파일을 수정할 때는 `dist/sw.js`의 `CACHE` 버전도 변경하세요.
